## The challenge

Build a platform able to support different organizations, users and clinical
workflows while keeping data isolated, business rules consistent and the
experience simple for the professionals who run sessions.

## Key technical challenges

- Multi-tenant architecture with data isolated per organization.
- Business rules centralized in the backend.
- A deterministic, testable decision engine.
- Idempotent operations to handle repeated and concurrent requests.
- Change history and traceability of results.
- Scheduling and recurrence system.
- Authentication, authorization and role-based access control.
- Stripe integration for billing.
- A web app and a mobile app consuming the same API contract.
- Automated testing strategies for business rules and integration.

## Engineering

The API is structured as a modular monolith, with a clear separation between
domain, application and infrastructure.

Critical logic stays on the server, so the different clients cannot diverge.

On the frontend, the architecture is organized by domain, with validation of the
API contracts and rules that prevent improper dependencies between modules.

## Outcome

The project let me work end to end on a real SaaS, covering API architecture,
data modelling, business rules, authentication, payments, cloud infrastructure,
web and mobile apps, and automated testing.

The project is still in development. Some technical and business details have
been left out for confidentiality.
