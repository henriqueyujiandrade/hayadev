## O desafio

Construir uma plataforma capaz de suportar diferentes organizações, usuários e
fluxos clínicos, mantendo isolamento de dados, consistência das regras de negócio
e uma experiência simplificada para profissionais que executam sessões.

## Principais desafios técnicos

- Arquitetura multi-tenant com isolamento de dados por organização.
- Centralização das regras de negócio no backend.
- Motor de decisão determinístico e testável.
- Operações idempotentes para lidar com requisições repetidas e concorrentes.
- Controle de histórico das alterações e rastreabilidade dos resultados.
- Sistema de agendamento e recorrência.
- Autenticação, autorização e controle de acesso por função.
- Integração com Stripe para cobrança.
- Aplicação web e aplicativo mobile consumindo o mesmo contrato de API.
- Estratégias de testes automatizados para regras de negócio e integração.

## Engenharia

A API foi estruturada como um monólito modular, com separação clara entre
domínio, aplicação e infraestrutura.

A lógica crítica permanece no servidor para evitar divergência entre os
diferentes clientes.

No frontend, a arquitetura foi organizada por domínio, com validação dos
contratos da API e regras para impedir dependências indevidas entre módulos.

## Resultado

O projeto me permitiu trabalhar de ponta a ponta em um SaaS real, envolvendo
arquitetura de APIs, modelagem de dados, regras de negócio, autenticação,
pagamentos, infraestrutura cloud, aplicações web/mobile e testes automatizados.
