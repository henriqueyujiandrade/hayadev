## El desafío

Construir una plataforma capaz de soportar distintas organizaciones, usuarios y
flujos clínicos, manteniendo el aislamiento de datos, la coherencia de las reglas
de negocio y una experiencia sencilla para los profesionales que ejecutan las
sesiones.

## Principales desafíos técnicos

- Arquitectura multi-tenant con aislamiento de datos por organización.
- Centralización de las reglas de negocio en el backend.
- Motor de decisión determinista y testeable.
- Operaciones idempotentes para gestionar solicitudes repetidas y concurrentes.
- Control del historial de cambios y trazabilidad de los resultados.
- Sistema de agenda y recurrencia.
- Autenticación, autorización y control de acceso por rol.
- Integración con Stripe para la facturación.
- Aplicación web y app móvil consumiendo el mismo contrato de API.
- Estrategias de tests automatizados para reglas de negocio e integración.

## Ingeniería

La API se estructuró como un monolito modular, con una separación clara entre
dominio, aplicación e infraestructura.

La lógica crítica permanece en el servidor para evitar divergencias entre los
distintos clientes.

En el frontend, la arquitectura se organizó por dominio, con validación de los
contratos de la API y reglas que impiden dependencias indebidas entre módulos.

## Resultado

El proyecto me permitió trabajar de punta a punta en un SaaS real, abarcando
arquitectura de APIs, modelado de datos, reglas de negocio, autenticación, pagos,
infraestructura cloud, aplicaciones web y móviles y tests automatizados.
