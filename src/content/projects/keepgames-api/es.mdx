## Sobre el proyecto

KeepGames API es el backend de una plataforma SaaS de juegos terapéuticos con
biofeedback, responsable de gestionar organizaciones, pacientes, profesionales,
sesiones de juego, telemetría, formularios y suscripciones.

Participé en el desarrollo de la API y del modelo de datos, incluida la
definición de las reglas de negocio y de las integraciones que necesitan los
distintos clientes de la plataforma.

## Principales desafíos técnicos

- Arquitectura **multi-tenant**, con aislamiento de datos entre organizaciones.
- Autenticación y autorización para distintos tipos de clientes.
- Comunicación segura entre el portal y los juegos.
- Registro y almacenamiento de la telemetría fisiológica asociada a las partidas.
- Modelado de datos para grandes volúmenes de registros de juego.
- Separación entre datos transaccionales y datos de telemetría.
- Formularios configurables y versionados.
- Reglas de negocio para suscripciones y control de acceso.
- Integración con **Stripe** para pagos y suscripciones.
- Operaciones idempotentes y consistencia transaccional.
- Tests automatizados para reglas de negocio y flujos críticos.

## Arquitectura

La API se desarrolló con **NestJS, TypeORM y PostgreSQL**, con una arquitectura
modular orientada a los dominios de la aplicación.

Las reglas de negocio están centralizadas en el backend, y los clientes — el
portal y los juegos — consumen una API única y controlada.

El modelado se diseñó para preservar la integridad de los registros históricos y
permitir la evolución de los juegos sin un acoplamiento excesivo entre sus
estructuras específicas.

## Datos y telemetría

Uno de los principales desafíos del proyecto fue gestionar datos de partidas
asociados a señales fisiológicas.

La arquitectura separa los datos transaccionales de la telemetría, lo que permite
almacenar grandes volúmenes de datos brutos sin afectar a las consultas
habituales de la aplicación.

La información necesaria para listados y análisis generales se mantiene de forma
optimizada, evitando cargar los datos brutos cuando no hace falta.
