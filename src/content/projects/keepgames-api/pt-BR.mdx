## Sobre o projeto

A KeepGames API é o backend de uma plataforma SaaS de jogos terapêuticos com
biofeedback, responsável por gerenciar organizações, pacientes, profissionais,
sessões de jogo, telemetria, formulários e assinaturas.

Atuei no desenvolvimento da API e do modelo de dados, incluindo a definição das
regras de negócio e das integrações necessárias para os diferentes clientes da
plataforma.

## Principais desafios técnicos

- Arquitetura **multi-tenant**, com isolamento de dados entre organizações.
- Autenticação e autorização para diferentes tipos de clientes.
- Comunicação segura entre o portal e os jogos.
- Registro e armazenamento de telemetria fisiológica associada às partidas.
- Modelagem de dados para grandes volumes de registros de jogo.
- Separação entre dados transacionais e dados de telemetria.
- Formulários configuráveis e versionados.
- Regras de negócio para assinaturas e controle de acesso.
- Integração com **Stripe** para pagamentos e assinaturas.
- Operações idempotentes e consistência transacional.
- Testes automatizados para regras de negócio e fluxos críticos.

## Arquitetura

A API foi desenvolvida com **NestJS, TypeORM e PostgreSQL**, utilizando uma
arquitetura modular orientada aos domínios da aplicação.

As regras de negócio são centralizadas no backend, mantendo os clientes — portal
e jogos — como consumidores de uma API única e controlada.

A modelagem foi projetada para preservar a integridade dos registros históricos e
permitir a evolução dos jogos sem acoplamento excessivo entre suas estruturas
específicas.

## Dados e telemetria

Um dos principais desafios do projeto foi lidar com dados de partidas associados
a sinais fisiológicos.

A arquitetura separa os dados transacionais das informações de telemetria,
permitindo que grandes volumes de dados brutos sejam armazenados sem impactar as
consultas comuns da aplicação.

As informações necessárias para listagens e análises gerais são mantidas de forma
otimizada, evitando o carregamento desnecessário dos dados brutos.

## Engenharia

Durante o desenvolvimento, trabalhei principalmente com:

- modelagem relacional;
- regras de negócio;
- multi-tenancy;
- autenticação e autorização;
- consistência transacional;
- idempotência;
- versionamento de dados;
- integração com serviços externos;
- processamento de telemetria;
- testes unitários e de integração;
- infraestrutura AWS.

regras de negócio**.
