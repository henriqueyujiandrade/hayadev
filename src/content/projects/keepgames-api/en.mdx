## About the project

KeepGames API is the backend of a SaaS platform of therapeutic biofeedback
games, responsible for managing organizations, patients, professionals, game
sessions, telemetry, forms and subscriptions.

I worked on the development of the API and the data model, including defining
the business rules and the integrations the platform's different clients need.

## Key technical challenges

- **Multi-tenant** architecture, with data isolated between organizations.
- Authentication and authorization for different kinds of clients.
- Secure communication between the portal and the games.
- Recording and storing the physiological telemetry tied to each match.
- Data modelling for large volumes of game records.
- Separating transactional data from telemetry data.
- Configurable, versioned forms.
- Business rules for subscriptions and access control.
- **Stripe** integration for payments and subscriptions.
- Idempotent operations and transactional consistency.
- Automated tests for business rules and critical flows.

## Architecture

The API was built with **NestJS, TypeORM and PostgreSQL**, using a modular
architecture organized around the application's domains.

Business rules are centralized in the backend, keeping the clients — the portal
and the games — as consumers of a single, controlled API.

The data model was designed to preserve the integrity of historical records and
to let the games evolve without excessive coupling between their specific
structures.

## Data and telemetry

One of the project's main challenges was handling match data tied to
physiological signals.

The architecture separates transactional data from telemetry, so large volumes of
raw data can be stored without affecting the application's everyday queries.

The information needed for listings and general analysis is kept in an optimized
form, avoiding loading the raw data when it is not needed.

evolving data models, external integrations and consistent business rules**.
